# 3.7.1 — 심박 측정 유실 · 세트 압박 시점 · 멘트 10개 · 리치 에디터 툴바 위 칸

3.7.0 배포 뒤 사용자 실기(iPhone 14 Pro, **iOS 27.0.1**)에서 나온 문제와 10/22 남은 일. 네이티브(Swift·RN 패치)가 바뀌어 **OTA 금지 — 3.7.1 새 바이너리**.
이 맥은 Xcode 26.5라 iOS 27 실기에 설치가 안 된다(DDI 마운트 실패) — 검증은 iOS 26.5 시뮬레이터("Pown Spike iPhone")에서 했고, 실기 확인은 아래 "남은 일".

## 1. 이어폰을 빼고 섬을 누르면 측정·기록이 사라짐 — 원인 확인·수정

수정 전 코드로 시뮬레이터에서 그대로 재현했다(가짜 이어폰·Darwin 알림으로 "이어폰 빠짐"·"시스템 종료"를 트리거하는 임시 코드, 지금은 지움).

| 시각 | 수정 전 앱 (SpringBoard·앱 로그) |
| --- | --- |
| 06:27:13 | 이어폰 빠짐 → 세션을 **일시정지만** 함. 일시정지 세션은 앱을 살려 둔다(Running) |
| 06:28:34.474 | iOS가 세션을 끝냄 → `closeBySystem`이 넘김 시작(`endCollection` …) |
| **06:28:34.505** | **15ms 뒤 iOS가 앱을 Suspended** — 넘김이 얼어붙음. 측정(`carried`)은 넘김 끝에 쓰므로 디스크에 없음. healthd는 "Slow workout end" |
| 06:30:01 | 섬을 눌러 앱이 깨어나서야 넘김이 마저 끝남 |

- 정지된 사이 메모리 회수로 죽으면 측정이 통째로 사라진다(다시 켜면 세션도 `carried`도 없어 남은 섬까지 끝냄). 깨어나도 그 순간 `recover()`는 nil을 줘 박스가 접히고, 넘김 결과는 앱이 `.active`일 때만 JS로 보내서 놓칠 수 있다. 이어폰·워치가 없으면 시작 버튼까지 숨어 "기능이 꺼진" 것처럼 보였다.
- 수정(`modules/heart-rate/ios/HeartRateModule.swift`)
  - 이어폰을 빼면 일시정지 대신 **바로** 그 구간을 저장하고 세션 없는 일시정지(suspended)로 넘긴다(`suspendSegment` — 시스템 종료·워치 전환과 같은 함수). 재개는 새 구간으로 잇는다(섬 재개 버튼은 앱을 연다).
  - 넘김·종료 마무리를 `beginBackgroundTask`로 감싸고 섬 갱신까지 보낸 뒤 놓는다. HealthKit 마무리 호출(`endCollection`·`finishWorkout`·샘플 조회)은 한도(5·10·5초)까지만 기다린다.
  - **구간 체크포인트**(UserDefaults `heartRateSegment`): 넘김·종료 시작 때와 재는 동안 30초마다 지금 구간 값을 남긴다. 다시 켤 때 `recoverActiveWorkoutSession()`이 *성공하고* 세션이 없다고 하면 그걸 `carried`에 접고, 멈춘 세션이 돌아오면 그 값으로 일시정지에 붙인다(종료를 누르던 중이었으면 기록으로 마무리). 조회가 실패(잠금 등)하면 아무것도 치우지 않는다.
  - 되찾은 멈춘 세션은 **멈춘 시각(`session.endDate`)까지만** 잰다 — 처음엔 죽어 있던 시간까지 들어가 51초가 86초가 됐다.
  - 함께: `start()`가 낡은 세션을 치우며 일시정지 측정까지 지우던 것, 0초 구간이 0:00 측정으로 남던 것, 넘김 중 재개·일시정지, 기다리던 종료 continuation을 버리던 것, 다시 켠 뒤 "이어폰이 빠져서…" 안내가 사라지던 것, `.inactive`(섬을 눌러 돌아오는 순간)에 JS로 안 보내던 것.
- 확인(수정 후): 이어폰 빠짐 2초 안에 `carried` 저장(82초·심박·건강 앱 구간) → 그 뒤 iOS가 앱을 Suspended → `kill -9` → 섬 탭 → "일시정지 1:22"·안내 그대로. 넘김 도중 kill → 멈춘 세션 복구로 0:44 정확. 세션 종료 뒤·저장 전 kill → `recover: folding checkpoint` → 0:24. 재개 → 새 구간 이어 재기 → 종료 시 "오늘 기록에 더했어요!"(구간 합침). 1분 미만 종료 → 저장 안 함 + purge. 3.7.0이 남긴 일시정지 측정도 새 코드가 그대로 이어받음. 섬(잠금화면 Live Activity)은 일시정지 상태로 남는다.

## 2. 세트 압박 알림 시점 — 사용자 규칙으로

- 측정 시작 뒤 **100 이상을 한 번 찍기 전엔 안 울린다**(80~90 시작 구간). 100 이상 → 무장, 그 뒤 **100 미만이 60초 이어지면** 1번 울리고 무장 해제 — 다시 100 이상을 찍어야 다음(쉬는 시간마다 1번, 사용자 결정). 쉬는 중 100 이상이 들어오면 60초를 다시 센다. 일시정지·알림 끔은 무장 해제, 신호 끊김(nil)은 셈 유지.
- 판정은 `modules/heart-rate/ios/RestAlert.swift`(Foundation만), 확인 스크립트 `scripts/check-rest-alert.swift` — 판정을 바꾸면 돌린다:
  `swiftc -parse-as-library modules/heart-rate/ios/RestAlert.swift scripts/check-rest-alert.swift -o /tmp/check-rest-alert && /tmp/check-rest-alert`
- 설명 문구: "100bpm 아래로 1분 쉬면 알람을 보냅니다" / "Alerts you after 1 minute below 100 bpm".
- 확인: 스크립트 7개 통과. 시뮬레이터에서 가짜 심박 85(40초)→120(20초)→92(90초)→125(15초)→95(80초) — 85 동안 무알림, **121.8초·226.7초에 1번씩**(예상 120·225초), 그 사이 반복 없음. 백그라운드 배너 확인.

## 3. 멘트 10개

기존 5개 + "그냥 집 가서 편하게 유튜브 보세요." · "쉬는 게 운동이면 이미 국가대표입니다." · "근손실 오는 소리 들리시나요?" · "폰 그만 보고 바벨 잡으세요." · "이렇게 쉴 거면 헬스장 회원권이 아깝습니다." (영어도 같이, `lib/i18n.ts`·`REST_ALERT_KEYS`). 시뮬레이터 배너에 새 멘트가 뜨는 것 확인.

## 4. 리치 에디터 — 긴 글이 툴바 위에서 가려짐

원인이 둘이었다.

- **긴 글의 끝이 스크롤로 안 올라옴(주원인, 10/22 남은 일 1과 같은 버그)**: 스크롤 높이(`contentSize`)를 enriched의 `measureSize`(글 사본을 `boundingRect`로 잼)로 정하는데, 이건 줄 간격 패치 5(줄마다 ×1.25)를 몰라 글을 실제보다 약 20% 짧게 잰다 — 40줄 글에서 33번째 줄까지만 스크롤되고 마지막 7줄은 툴바·키보드 뒤에 갇혔다. 문서 끝에 줄을 더하면 커서가 키보드 뒤로 내려가던 것도 이것(10/22엔 비동기 `contentSize`로 추정했다). → 패치 9가 실제 레이아웃 높이(`usedRectForTextContainer`)로 잰다. 10/22 판이 걸린 node_modules는 같은 패치의 이행 항목이 바꾼다.
- **툴바 위 34pt 칸**: RN `InputAccessoryView` 내용 뷰가 처음 잰 안전영역(홈 인디케이터 34)을 키보드 위에서도 높이에 남겨 툴바 위에 칸이 생겼다. 10/22엔 그 칸을 투명하다고 보고 본문을 34만큼 그 뒤로 늘렸는데(추정값), iOS 27에선 그 칸이 글을 가릴 수 있다. → `scripts/patch-enriched.js` 4-1(`RCTInputAccessoryContentView.mm`: 안전영역이 바뀌면 크기를 다시 잼)로 칸을 없애고, JS(`note-toolbar-dock.ios.tsx`)는 추정값 34를 걷어 본문 여백 = 키보드(보조 막대 포함) 높이.
- 함께: 패치 10 — `_performRelayout`이 크기를 넣은 뒤 포커스 중이면 커서 줄 + 아래 여백이 보이게 스크롤.
- 확인(iOS 26.5, 디버그 코드 없는 빌드): 화면 키보드에서 툴바 윗변 539pt·키보드 윗변 583pt — 툴바 44pt가 키보드에 바로 붙고 칸이 없다. 40줄을 붙여넣으면 화면이 바로 40번째 줄 끝(커서)으로 따라오고, 끝까지 스크롤된다(수정 전엔 33번째 줄에서 멈춤). 화면 자판으로 끝에 8줄(엔터+ㅎ)을 더하는 동안 마지막 줄이 툴바 위 여백 안에 계속 보인다. 키보드가 올라오는 녹화(60fps, 194프레임)에서 툴바는 처음부터 자판 바로 위에 붙어 올라와 539pt에 멈추고 튀지 않는다. 하드웨어 키보드에선 툴바가 홈 인디케이터 위에 선다. `patch-enriched.js`는 깨끗한 0.4.1에 두 번 돌려 처음엔 11/12(이행 항목은 원래 안 걸림)·두 번째 0, 10/22 판 node_modules엔 이행 1건이 걸림.

## 검증 환경 메모

- 시뮬레이터 앱 RunningBoard는 측정 세션이 끝나면 앱을 바로 Suspended로 만든다 — SpringBoard 로그 `Setting process task state to: Suspended`로 볼 수 있다(`xcrun simctl spawn <sim> log show --predicate 'process == "SpringBoard" AND eventMessage CONTAINS "<pid>"'`).
- 섬 내용은 `simctl io screenshot`에 안 찍힐 때가 많다 — 잠금화면(Device > Lock → Home)으로 확인.
- 시뮬레이터 데이터: "Pown Spike iPhone"에 10/23 벤치프레스 60kg 계획과 심박 기록 몇 개가 남아 있다. I/O > Keyboard > Connect Hardware Keyboard를 껐다.
- 디스크: 이 워크트리 `ios/build`가 약 5GB — Android를 빌드하기 전에 지울 것(`ios/build/generated`는 남김).
