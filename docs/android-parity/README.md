# 안드로이드 ↔ iOS UI/UX 일치 체크리스트

안드로이드 앱이 iOS 앱을 **복사한 것처럼** 보이고 움직이게 만드는 작업의 진행표다. 세션마다 이 파일을 열고 이어서 한다.

**현황 (2026-10-16)**: `[x]` 137 · `[ ]` 24 (출시 전 코드 밖 작업 3 포함) · `[-]` 7 — 세션이 끝날 때마다 이 줄과 맨 아래 진행 로그를 갱신한다.

## 사용법 (다음 세션)

1. 아래 "비교 환경"대로 iOS 시뮬레이터·안드로이드 에뮬레이터를 같은 데이터·같은 언어로 띄운다.
2. 이 파일의 `[ ]` 항목을 **위에서부터** 두 기기 나란히 비교하며 고친다. 고치고 다시 재서 맞으면 `[x]` + 판정 한 줄.
3. 화면 묶음 하나 끝날 때마다 `npm run typecheck && npm run lint` → 이 파일 갱신 → WIP 커밋.
4. 세션 끝(5시간 사용량 95%)에는 맨 아래 **진행 로그**에 한 줄 쓰고 커밋·푸시·PR.

## 비교 환경

| | iOS | Android |
|---|---|---|
| 기기 | iPhone 17 Pro 시뮬레이터 `2C2ADC51-E0FB-4BF5-81AF-CCF7FCD9B7B4` | `Pixel_6_API_35` 에뮬레이터 |
| 단위 | 스크린샷 ÷ 3 = pt | 스크린샷 ÷ 2.625 = dp |
| 세로 기준 | 안전영역 위끝 62pt | 안전영역 위끝 48.76dp (펀치홀 컷아웃 켠 상태) |
| 다크 | `xcrun simctl ui $SIM appearance dark` | `adb shell cmd uimode night yes` |

- 앱은 dev-client가 깔려 있으면 재빌드 없이 Metro만 띄운다: `npx expo start --dev-client` + `adb reverse tcp:8081 tcp:8081`.
- **컷아웃 확인**: 콜드 부팅하면 컷아웃 에뮬레이션이 꺼져 있을 수 있다 — 그러면 상태바가 24dp라 헤더가 카메라 구멍에 붙는다(앱 문제 아님). `adb shell cmd overlay enable-exclusive --category com.android.internal.display.cutout.emulation.emu01` → `dumpsys window | grep statusBars`가 128px(48.76dp)인지 본다.
- 같은 데이터: iOS MMKV(`Documents/mmkv/mmkv.default{,.crc}`)를 **복사본으로** 읽어 안드로이드 `files/mmkv/`에 넣는다(verify 스킬 §7). 로케일 ko-KR.
- 사진·숏츠: 저장 경로가 `media/...` 상대 경로라 iOS `Documents/media/*`를 안드로이드 `files/media/`에 같이 넣으면 같은 사진·영상이 뜬다. **미디어를 먼저 넣고 MMKV를 나중에** — 반대로 하면 첫 실행의 숏츠 복구(`onRepairVideos`)가 파일 없는 숏츠를 지운다.
- 심박 기록이 있는 날짜는 iOS에만 심박 띠가 붙으니 비교에서 피한다.
- 화면 높이가 다르다(iOS 874 / Pixel 6 914). 위에 붙은 요소는 안전영역 위끝, 아래에 붙은 요소(탭바·FAB·뷰어 하단 바)는 **안전영역 아래끝**(iOS 840 / 안드 890.3), 가운데 뜨는 다이얼로그는 화면 중앙 기준으로 비교한다. 폭도 402 / 411이라 화면 폭에 비례하는 것(숏츠 타일·드로어 폭·태그 줄바꿈)은 같은 규칙인지만 본다.
- 키보드 검증: AVD `config.ini`의 `hw.keyboard = no` + 콜드 부팅(끝나면 `yes`로 원복).
- 3버튼 내비 확인: `adb shell cmd overlay enable-exclusive --category com.android.internal.systemui.navbar.threebutton` (되돌리기 `...navbar.gestural`). 하단에 떠 있는 버튼이 내비 바(48dp)에 겹치지 않는지 본다.
- Metro를 다시 띄웠으면 앱도 다시 붙인다(안드로이드는 딥링크로 재시작) — 안 그러면 옛 번들로 돌아 수정이 안 보인다.
- 5시간 사용량: `cat ~/.claude/state/five-hour-pct` (상태줄 스크립트가 써 둔다. 첫 값이 %, 둘째가 기록 시각).
- 애니메이션(전환·드로어)은 정지 프레임으로 판정하지 않는다 — 중간 프레임에서 움직이는 방향까지만 확인한다(verify 5-1).

- [x] **여러 줄 글·명시 lineHeight**: lineHeight 20(52.5px)을 안드로이드가 줄마다 53px로 올려 줄마다 +0.19 — AI 리포트 카드가 장마다 +0.5씩 밀려 다섯째 카드 +2.05. `sbLineHeight`를 일반화: 줄마다 가장 가까운 픽셀 + iOS 상자 높이(⅓pt 올림)와의 차이를 `marginBottom`으로, lineHeight를 명시한 글은 테마 Text가 `onTextLayout`으로 줄 수를 재 넘긴다(그 외 글은 한 줄로 계산 — 모든 글에 이벤트를 달면 목록이 무거워진다). 리포트 카드 위끝 다섯 장 ±0.15, 운동 카드·캘린더 그대로
- [x] **아이콘 글꼴 줄**: 원인 — 안드로이드는 아이콘 글꼴도 글리프 외곽(includeFontPadding)·ascent/descent 픽셀 올림으로 20 아이콘 박스가 20.57(꺼도 20.19). 아이콘 박스를 iOS 줄 높이로 못박는 `iconLine(size, ratio)`(text-metrics 쌍, iOS는 undefined)을 아이콘이 행 높이를 정하는 곳에 적용: 계획 폼 섹션 제목 6곳(Octicons는 1.0156배)·제목 줄 검색·운동 카드 ⋯·드로어 톱니/폴더 트리/빈 상태, 설정 행 아이콘은 `height: 20`. node_modules 아이콘에 임시 배경색을 칠해 두 기기 박스를 재서 확인(iOS 20.00 / 안드 52px=19.81, 박스 배경은 54px로 그려지지만 레이아웃은 52px — uiautomator 확인). 계획 폼 끝 +3.57 → ±0.7 무누적, MY 끝 +1.15 → +0.39, 드로어 폴더 행 +0.91 → −0.24
