# 3.7.3 — 심박 측정 기록 유실 · 세트 압박 오판 · 워치 경로 정리

3.7.2 배포 뒤 사용자 보고 "측정이 이유 없이 끝나고 기록도 안 남았다(세트 압박 알림 때문인 것 같다)"로 심박 기능 전체를 코드 리뷰했다(후보 27건 검증, 반박된 것 없음). 네이티브(아이폰 모듈·워치 앱)가 바뀌어 **OTA 금지 — 3.7.3 새 바이너리로 배포**.

**세트 압박 알림은 측정을 끝내거나 기록을 지우지 않는다** — `checkRestAlert`·`RestAlert`·`ForegroundNotifications` 어디에도 그런 호출이 없다(세 번 따로 추적). 증상은 아래 1의 경로들로 설명된다. 알림 자체엔 따로 오판(세트 도중 울림·안 울림)이 있었다(2).

## 1. 측정이 끝나 보이거나 기록이 사라지던 경로

| 증상 | 원인 | 수정 |
| --- | --- | --- |
| 앱이 뒤에 있을 때 끝난 측정(워치에서 종료·섬 종료·시스템 종료)의 기록이 없음 | 요약을 JS로 보내기만 하고 사본이 없었다 — JS가 저장하기 전에 앱이 정지·회수되면 끝 | 요약은 JS가 저장했다고 알릴 때(`ackEnded`)까지 디스크(`heartRatePendingEnded`)에 두고 JS가 들을 때마다 다시 넘긴다. 앱 종료 버튼의 `end()` 반환값도 같다. 워치 종료 경로에 백그라운드 시간 |
| 앱이 콜드 스타트하며 넘겨받은 요약에서 예외 | Toaster가 그려지기 전(글꼴 로딩 중) `toast()`가 던졌다 | `saveRecord`의 토스트만 try/catch — 기록은 남는다 |
| 한꺼번에 넘겨받은 기록 하나를 지우면 같이 지워짐 | 같은 ms라 `Date.now()` ID가 겹쳤다 | `addRecord`가 겹치지 않는 ID를 고른다 |
| 워치 측정 중 앱이 죽었다 다시 켜면 3초 만에 섬이 사라짐(워치는 계속 잼) | `recover()`가 미러를 3초만 기다리고 섬을 끝냈다 — 끊긴 워치는 5~60초 간격으로 다시 붙는다 | 페어링된 워치가 있으면 남은 섬을 75초 두었다 치운다(붙으면 그 섬을 이어 쓴다). 섬의 X는 바로 치운다 |
| 그 상태에서 다시 시작하면 앞 워치 측정 기록이 사라짐 | 워치가 앞 측정의 마지막 값을 안 보내거나(끊긴 줄 모름), 아이폰이 시작·재개 중이라 버렸다. 측정이 없을 땐 `reset()`이 지금 측정의 체크포인트까지 지웠다 | 워치는 새 시작으로 닫는 측정·미러 전송이 실패한 마지막 값을 WCSession으로 보낸다(되찾은 측정도). 아이폰은 그 값이 지금 측정 것이면 마무리, 일시정지 측정에 이어 재던 구간이면 앞 구간에 붙이고, 아니면 지금 측정은 건드리지 않고 따로 기록(1분 이상). JS는 지난 측정의 요약이면 박스를 접지 않고, 이미 남긴 측정(건강 앱 운동 시작이 겹침)이면 거른다 |
| 에어팟을 빼고 바로 앱을 열면 박스가 접힘(기기 없으면 카드째) | 넘기는 동안(최대 약 25초) `recover()`가 nil | 넘기는 동안엔 넘긴 뒤의 일시정지를 보여준다. 그 사이 누른 재개는 넘김이 끝난 뒤 잇는다 |
| 일시정지 측정을 워치로 잇는 중 섬 X → 박스만 접히고 측정은 남음 / 워치 전환 직후 섬 X 무시 / 그 사이 전체 초기화 뒤 측정이 되살아남 | 종료가 진행 중인 재개·전환을 기다리지 않았다 | 종료 수(`endRequests`)를 세어 재개·전환·넘김이 이어 재지 않게 하고, 종료는 시작이 풀리길 기다렸다 남은 측정을 끝낸다. 워치 전환의 넘김도 `suspending`에 걸어 종료가 기다린다 |
| 잠긴 기기에서 섬 X → 앱이 죽으면 종료가 사라짐, 풀린 뒤 끝내면 기록이 미룬 만큼 길어짐 | 미룬 종료가 메모리에만 있고 "지금"으로 멈췄다 | 누른 시각을 디스크(`heartRateEndRequested`)에 두고 그 시각으로 멈춘다 |
| 되찾은 멈춘 세션의 기록이 죽어 있던 시간만큼 길어짐 | 수집 종료가 한도(5초)를 넘기면 경과 시간을 "지금"으로 셌다 | 경과 시간·체크포인트를 멈춘 시각(`session.endDate`)으로 잰다. 워치도 되찾은 멈춘 세션을 멈춘 시각으로 끝낸다 |

## 2. 세트 압박 알림 오판 (`RestAlert.swift`)

뼈대는 그대로(쉬던 최저보다 15 오르면 세트, 세트 최고에서 내려오면 휴식, 휴식 N초 넘으면 1번)이고 잡음에 강하게만 바꿨다.

- 다음 세트를 시작해 오르는 중(`rising`)엔 울리지 않는다 — 고른 휴식 시간쯤 다음 세트를 시작하면 세트 초반에 울렸다.
- 최근 심박 셋의 가운데 값으로 판정 — 튄 값 하나(세트 중 175)가 최고가 돼 세트 도중 휴식이 시작됐다.
- 세트 끝: 최고에서 **15** 내려오거나(10은 흔들림 폭과 같았다) 최고 언저리(±5)를 60초 못 찍으면. 평탄하게 흔들리는 긴 세트가 도중에 끝나지 않는다.
- 세트 직후 신호가 끊겨도 60초가 지나면 휴식이 시작된다 — 예전엔 영영 안 울렸다.
- 앞 세트 최고까지 다시 오르면 +10만 올라도 세트 — 짧게 쉬어 덜 내려온 채 시작한 다음 세트(140 → 128 → 141)를 못 잡아 그 세트 도중 울렸다.
- 판정엔 **새 심박 샘플만 그 시각으로** 넣는다(아이폰 `recordSample`, 워치는 새 `WatchSnapshot.heartRateAt`). 화면 갱신마다 마지막 심박을 지금 시각으로 다시 넣어 튄 값 하나가 칼로리 갱신에 실려 세트(20초)를 혼자 채웠다. `heartRateAt`을 안 보내는 옛 워치 앱은 예전처럼 받을 때마다 넣는다.
- 울린 시각은 알림을 띄우기 전에 남긴다(띄우는 사이 끝난 측정의 요약에서 빠졌다). 알림이 못 나가면 뺀다.

확인 스크립트(`scripts/check-rest-alert.swift`) 19개 — 새 5개(휴식 끝에 다음 세트·세트 중 튄 값·평탄한 긴 세트·덜 내려온 채 다음 세트·세트 뒤 바로 끊김)는 옛 판정에서 전부 틀린다. 가운데 값 때문에 바뀐 심박을 한 샘플(5초) 늦게 먹어 기존 기대값이 5초씩 밀렸다.

## 3. 그 밖

- 재개 직후 첫 심박 전에 "신호 없음"·워치 전환 버튼이 뜸 → 신호 없음은 이번에 재기 시작한 때부터 센다(합친 경과 시간으로 셌다).
- 준비 3초 사이 이어폰을 빼면 심박 없는 "측정 중"이 됨 → 준비가 끝날 때 이어폰을 다시 본다(`ERR_NO_DEVICE`).
- 워치 명령 전송(`sendCommand`)에 한도 — 답이 없으면 종료가 안 풀려 앱을 다시 켤 때까지 측정을 못 했다.
- 되찾은 아이폰 세션의 그래프 샘플을 체크포인트에서 되살린다.
- Live Activity 갱신에 보낸 시각(`timestamp`) — 늦게 닿은 옛 값이 새 값을 덮지 않게.
- 측정 박스의 1초 틱은 앱이 뒤에 있으면 멈춘다.

## 안 고친 것

- **워치로 이어 재던 측정에서 앱이 죽었다 켜졌는데 워치가 아직 다시 안 붙은 동안**(최대 약 60초) 박스는 일시정지로 보인다. 그 사이 종료하면 기록이 둘로 나뉘고(데이터는 남는다), 이어폰으로 재개하면 그 워치 구간은 앱 기록에서 빠진다(건강 앱엔 있다). 고치려면 워치 구간도 체크포인트로 남겨야 해 실기 확인 없이 넣지 않았다.
- 워치 앱이 죽었다 되찾은 측정은 "짧아도 남기기"·"버리기" 표시를 잃는다(드묾).
- 체크포인트와 앞 구간 쓰기 사이에 앱이 죽으면 한 구간이 두 번 더해질 수 있다(동기 코드 두 줄 사이).
- 알림 권한은 있는데 알림 스타일을 꺼 둔 경우도 "울림"으로 기록한다. 에어팟 자동 전환(다른 기기로 넘어감)은 뺀 것으로 본다.
