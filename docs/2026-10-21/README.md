# 전체 노트·숏츠 메모 리치 텍스트 에디터

전체 노트와 숏츠 메모 본문을 리치 텍스트로 바꿨다. iOS·Android 모두 끝났다 — Android 남은 작업(한글 조합 서식·제목 줄 높이·숏츠 메모 시트)은 10/22에 처리했다(아래 "10/22 처리"). 남은 건 삼성 키보드 실기 확인 하나다.

- 라이브러리: `react-native-enriched@0.4.1` (Software Mansion, Expo 리치 텍스트 가이드 1순위). RN 0.79를 지원하는 마지막 판이라 **버전 고정**. 0.5+와 후속 `react-native-enriched-html`은 RN 0.81+ → SDK 54 이상으로 올릴 때 옮긴다.
- 서식 9종: 굵게 · 밑줄 · 취소선 · 제목1 · 제목2 · 글머리 · 번호 · 체크리스트 · 인용. 글자색·이탤릭은 넣지 않았다(글자색은 라이브러리 API가 없고, 이탤릭은 iOS가 sb 글꼴·한글 기울임을 합성하지 않는다).
- 네이티브 의존성이 추가돼 **OTA 금지** — version·runtimeVersion 3.7.0.

## 10/22 처리

### 1. Android 한글 조합 중 서식 토글 — 완료 (패치 7)

- 원인: 안드로이드 글 버퍼(`SpannableStringBuilder`)는 바꿔 넣는 자리를 **꼭 맞게 덮은** 서식(`EXCLUSIVE_EXCLUSIVE`)은 새 글자 전체로 늘리고, 그 **안에 든** 서식은 지운다. Gboard는 조합 중인 글자(때로는 단어 전체)를 통째로 갈아 끼운다 — '핳'→'하하'에서 굵게가 0-2로 늘고, 스페이스에 단어 전체를 확정할 때 안에 든 첫 글자 굵게가 지워졌다. 예전 시도("늘어난 구간만 잘라 내기")가 첫 글자 굵게까지 잃은 이유가 이것이다.
- 해결: iOS 패치 3과 같은 방식 — 갈아 끼우기 전 글자마다 서식을 기억했다가, 원래 있던 자리는 원래 서식, 늘어난 글자는 지금 칠 서식(`spanState`)으로 돌려놓는다. 조합 중인 글자를 갈아 끼울 때만 한다(선택 영역에 친 글자·붙여넣기는 라이브러리 그대로).
- 확인 (Pixel 6 API 35, Gboard 한국어): 재현 순서 → "**하**하하 **하하**"(스페이스로 확정 뒤에도 유지), 밑줄·취소선 같음, 조합 중 굵게 켜기 "하**하하**", 조합 중 백스페이스 "하**핳**", 저장 뒤 읽기 화면도 같다.
- [ ] **삼성 키보드는 확인 못 했다** — 에뮬레이터에 설치할 수 없다. 갈아 끼우는 단위(글자/단어)가 달라도 같은 처리로 맞도록 만들었지만, 갤럭시 실기에서 위 재현 순서를 한 번 쳐 볼 것.

### 2. Android 제목 줄 높이 — 완료 (패치 5 수정 + 8)

- 줄 간격을 배율(×1.235)로 곱하면 반올림 때문에 나올 수 없는 줄 높이가 생긴다(18 제목은 70 다음이 72 — iOS 70.8에 맞는 71이 불가능). 줄 간격을 **(1.5em − 정수 지표)를 더하는** 방식으로 바꿨다 — 본문 줄은 그대로 63px(24.0), 제목 줄은 `LineHeightSpan`이 정한다.
- 결과: H1 79px(30.10, iOS 29.98), H2 71px(27.05, iOS 26.98). 본문·H1·본문·H2 뒤 줄 누적 −0.57 → +0.19pt. 픽셀 정수라 이보다 가까워질 수 없다.

### 3. Android 숏츠 메모 시트 — 완료

검증하며 찾은 문제 셋을 고쳤다.

- **서식 툴바가 안 보임**: 시트(gorhom, `keyboardBehavior="extend"`)는 키보드가 뜨면 내용 영역을 스스로 줄이는데, 독은 거기서 또 키보드 높이만큼 올라가 시트 위로 날아갔다. 독이 부모 아래끝과 화면 아래끝의 거리를 재서(키보드가 움직이는 동안 + 멈춘 뒤 90프레임만) 그만큼 덜 올린다 — 툴바가 키보드 윗변에 정확히 붙는다. 전체 노트 모달은 거리 0이라 예전과 같다.
- **커서 줄이 툴바 뒤에 숨음**: 시트가 다 줄어도 키보드 윗변보다 24 아래(시트가 아래 안전영역을 빼고 줄인다)에서 끝나 본문 끝 24가 툴바에 가렸다. 본문 칸 여백을 독이 잰 거리로 계산한다(`useNoteSheetEditorInset`, iOS는 지금처럼 0).
- **키보드 없이 툴바가 떠 있음**: reanimated는 `useAnimatedKeyboard`를 쓰는 화면이 하나도 없으면 키보드 감시를 멈추고 마지막 상태를 둔다. 전체 노트를 키보드 띄운 채 저장하면 "열림 336"이 남아 다음에 연 숏츠 메모에 툴바가 떠 있었다. 안드로이드 루트(`platform-root.android`)에서 늘 구독한다.
- 확인: 작성·서식(한글 조합 포함)·자동 저장·다시 열기, 키보드 내리기 버튼, 긴 글에서 커서 줄이 툴바 바로 위에 보임.

### 4. 함께 고친 회귀 — 노트 저장 뒤 숫자 키패드

- 전체 노트를 키보드 띄운 채 저장(또는 X)하면 계획 폼 '목표 중량'에 포커스가 가며 숫자 키패드가 뜨고 폼이 그쪽으로 스크롤됐다. 안드로이드는 포커스된 뷰가 화면째 사라지면 남은 화면의 첫 입력칸에 포커스를 넘긴다 — RN `TextInput`은 언마운트 때 스스로 blur해서 안 걸렸는데 enriched 에디터는 그러지 않았다(예전 본문 입력칸엔 없던 회귀).
- `RichNoteEditor`가 포커스된 채 언마운트되면 먼저 blur한다(`components/rich-note.tsx`).

### 5. 스크롤한 글이 디바이더·툴바까지 지나가게 (패치 9)

- 증상: 스크롤하면 글이 디바이더가 아니라 그 14 아래에서 사라지고, 툴바 위에도 투명한 띠가 생겨 글을 가렸다. 에디터 `paddingTop/Bottom: 14`가 두 플랫폼 모두 "자르는 선"으로 동작했다(iOS는 RN이 프레임을 패딩만큼 줄이고, Android TextView는 스크롤 중 패딩 선에서 잘라 그린다).
- 해결: 패딩을 스크롤되는 내용 여백으로 바꿨다(iOS 메모 앱 방식). 처음·끝에선 14만큼 띄워 보이고, 스크롤 중엔 글이 에디터 위끝(디바이더)·아래끝(툴바 윗변)까지 지나간다. JS 레이아웃은 그대로다.
- 함께: Android에서 키보드 칸이 툴바보다 낮을 때(하드웨어 키보드 — 24) 툴바는 그만큼만 올라오는데 본문은 툴바 전체를 비워 툴바 위에 20짜리 빈 띠가 생겼다. 본문 여백을 툴바 실제 자리(키보드 + min(툴바, 키보드))로 맞췄다(`note-toolbar-dock.android`).
- 함께(iOS): RN `InputAccessoryView`는 화면 아래에 있을 때 잡은 홈 인디케이터 안전영역(34)만큼 높이를 더 가지고 키보드 위에 붙어, 툴바 위에 투명한 칸이 생긴다 — 키보드 높이만큼 비운 본문 아래에 빈 박스가 보였다(키보드 위끝 495, 툴바 위끝 529). 소프트 키보드가 뜨면 그 칸만큼 본문을 덜 비운다(숏츠 메모 시트는 본문을 그만큼 늘린다, `note-toolbar-dock.ios`). 보조 막대 안에선 `measureInWindow`가 0이라 툴바 자리를 잴 수 없어 안전영역 값으로 본다.
- 원래 있던 문제(이번 변경과 무관, A/B 빌드로 확인): iOS에서 문서 **끝**에 줄을 계속 추가하면 커서 줄이 키보드 뒤로 내려가고 화면이 따라오지 않는다(문서 중간 입력은 따라온다). enriched가 `contentSize`를 비동기로 덮어써서로 보인다 — 다음 작업.
- 확인: iOS 시뮬레이터(iPhone 17 Pro)·Android 에뮬레이터에서 전체 노트에 30~40줄을 넣고 위·가운데·끝으로 스크롤 — 위는 디바이더 선에서, 아래는 툴바 윗변에서 글이 잘리고, 맨 위에선 디바이더 아래 14 여백이 그대로다. 입력 중 커서 줄이 따라 올라온다.

### 6. 함께 고친 원래 버그 (10/21, 확인용)

- 숏츠 메모: 시트가 이미 키보드만큼 내용 영역을 줄이는데 본문 칸이 키보드 높이를 한 번 더 빼서, 키보드가 뜨면 본문 칸이 0으로 접혀 안 보였다.
- 계획 폼 '기구 종류': 스크롤뷰 안 `flex: 1`로 높이가 0으로 접혀 테두리 윗변만 선처럼 보였다.

## 검증

- 타입 체크 두 플랫폼 · 린트 에러 0. `scripts/patch-enriched.js`는 깨끗한 0.4.1 소스에 처음부터 돌려 11개 파일 패치가 모두 걸리는 것과(10/22 패치 9 포함), 두 번 돌려도 한 번만 걸리는 것을 확인했다.
- 10/22 변경은 Android 에뮬레이터(Pixel 6, API 35)에서 확인했다. 패치 9는 iOS 시뮬레이터(iPhone 17 Pro)도 새로 빌드해 확인했다. 그 밖의 iOS 동작은 바뀌지 않는다(시트 본문 여백은 전과 같은 0, 에디터 언마운트 blur는 RN `TextInput`과 같은 동작).
- iOS 시뮬레이터(iPhone 17 Pro)·Android 에뮬레이터(Pixel 6, API 35)에서 같은 노트를 pt/dp로 나란히 비교했다. 첫 줄은 예전 본문 입력칸과 같은 자리(iOS 16.0pt / Android 16.0dp), 줄 간격 24.0.
- 툴바·키보드 동기화는 화면 녹화 프레임으로 확인 (iOS 매 프레임 ±1px, Android 5~7px 일정).
- 시뮬레이터 데이터: iOS에 오늘 날짜 "바벨 벤치프레스 60kg" 예시 계획(전체 노트 예시)이 남아 있다. 확인 후 지워도 된다. Android 에뮬레이터에는 iOS 데이터 복사본을 넣었다.
